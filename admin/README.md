# Albatros — панель управления (admin)

Git-based CMS для сайта albatros-website. Панель редактирует те же файлы, из
которых собирается статический сайт (`src/data/catalog.json` и изображения в
`public/images/products`), и делает локальные git-коммиты. Панель это отдельное
приложение внутри репозитория и НЕ входит в сборку Next.js.

## Состав

- `server/` — бэкенд на Node + Express (порт 4000): вход, чтение/запись контента,
  обработка изображений (sharp), git-коммиты (simple-git).
- `client/` — интерфейс на Vite + React + Tailwind (порт 5173 в режиме разработки).

Фаза 1: всё работает локально. Коммиты только локальные, публикации (push/deploy)
нет. Публичный сайт не изменяется (только файлы контента и фото).

## Установка

Нужен Node.js 18+ (проверено на Node 24).

```bash
# бэкенд
cd admin/server
npm install
cp .env.example .env          # затем впишите свой JWT_SECRET

# интерфейс
cd ../client
npm install
```

### Настройка .env (admin/server/.env)

- `PORT` — порт бэкенда (по умолчанию 4000).
- `CLIENT_ORIGIN` — адрес интерфейса (http://localhost:5173).
- `SITE_ROOT` — путь к корню репозитория сайта. По умолчанию вычисляется как три
  уровня вверх от `admin/server/src`, что верно, когда `admin/` лежит внутри репо.
- `JWT_SECRET` — секрет для подписи токенов. ОБЯЗАТЕЛЬНО замените на длинную
  случайную строку:
  `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`
- `JWT_EXPIRES_IN` — срок жизни сессии (по умолчанию 12h).
- `ANTHROPIC_API_KEY` — НЕОБЯЗАТЕЛЬНО: ключ Anthropic API для кнопки
  «Черновик UZ» (авточерновик узбекского перевода из русского текста).
  Без ключа панель полностью работает, узбекский текст вводится вручную.
  Ключ уже есть у владельца (используется в alba-bot); новый можно создать на
  platform.claude.com. Ключ хранится только в .env и не попадает в git.

Файлы `.env` и `users.json` в `.gitignore` и в git не попадают. На новой машине
их нужно создать заново (`.env`) и завести пользователей (`adduser`).

## Создание администратора

```bash
cd admin/server
npm run adduser                       # спросит имя, email, пароль
# или без вопросов:
npm run adduser -- "Саид" said@albatros.uz "надёжный-пароль"
```

Пользователи хранятся в `admin/server/users.json` (bcrypt-хэши, файл в .gitignore).

## Запуск

Два процесса в отдельных терминалах:

```bash
# терминал 1 — бэкенд
cd admin/server
npm run dev            # http://localhost:4000

# терминал 2 — интерфейс
cd admin/client
npm run dev            # http://localhost:5173
```

Откройте http://localhost:5173, войдите созданным пользователем.

## Что умеет (Фаза 1)

- Вход по email + паролю (bcrypt), сессия в httpOnly cookie (JWT). Все страницы и
  API защищены; выход очищает сессию.
- Список продуктов: фото, название, категория, бренд, приоритет, статус
  (опубликован/скрыт). Поиск и фильтр по категории.
- Редактирование продукта: фото (загрузка, порядок, удаление; каждое приводится к
  белому холсту 1000×1000), краткое и полное описания на RU и UZ, категория,
  общее направление, бренд, приоритет, флаги (скрыт/рекомендуемый/новинка),
  характеристики.
- Добавление продукта с проверкой обязательных полей.
- Скрытие/удаление (с подтверждением).
- Каждое сохранение это локальный git-коммит от имени вошедшего администратора.

## Что добавлено (Фаза 2)

- Партнёры: логотип (обрезка полей, прозрачность, веб-размер), специализация и
  описание на RU/UZ, сайт, год, страна; порядок стрелками, скрытие, удаление.
  Новый партнёр сразу появляется в выпадающем списке брендов у продуктов.
- Клиенты: логотип, описание RU/UZ, необязательная ссылка; порядок, скрытие,
  удаление. Отображаются в секции клиентов на странице «О компании».
- Сертификаты: скан-изображение (обязательно), названия RU/UZ, необязательный
  полный PDF; порядок, удаление. Секция «Сертификаты» на странице «О компании»
  показывает карточки и открывает документ по клику.
- Мероприятия: названия RU/UZ, месяц + год (формат данных «Месяц ГГГГ»), тип
  (семинар/конференция/конгресс/симпозиум/выставка/инсталляция/регистрация/другое),
  несколько фото (веб-сжатие, порядок, удаление), описания RU/UZ со счётчиком слов
  (цель ~90), приоритет, скрытие. Публичная страница мероприятий показывает
  карточки с фото и фильтрами по году и типу; скрытые не показываются.
- Прайс-лист: замена public/price-list.pdf с проверкой, что файл это PDF; адрес
  не меняется, кнопки «Скачать прайс-лист» продолжают работать.
- Все сохранения, как и раньше, это локальные git-коммиты от имени администратора.

Примечание: флаг «Скрыт» у партнёров и клиентов пока сохраняется только в данных,
публичный сайт начнёт учитывать его в следующей фазе. У мероприятий и
сертификатов скрытие уже работает на сайте.

## Что добавлено (Фаза 3)

- История изменений: вкладка «История» показывает все правки контента через
  панель (кто, когда, раздел, что изменено) с деталями и диффом. Кнопка
  «Откатить» создаёт НОВЫЙ коммит-отмену (история не переписывается); при
  конфликте откат отменяется автоматически с понятной ошибкой.
- Черновик UZ: рядом с каждым узбекским полем есть кнопка «Черновик UZ»,
  которая переводит русский текст в узбекский черновик (значок «черновик,
  проверьте» висит, пока текст не отредактирован). Требует ANTHROPIC_API_KEY
  в admin/server/.env (см. выше); без ключа кнопка объясняет, что нужно сделать.
- Сертификаты получили флаг «Скрыт» и публичную секцию на странице
  «О компании» (заголовки RU/UZ, документ открывается по клику, скрытые не
  показываются, пустой раздел выглядит аккуратно).

## Важно

- Панель пишет контент ровно в существующей схеме сайта. Компоненты, страницы и
  конфигурацию публичного сайта панель не трогает.
- Поля `hidden` и `priority` добавлены обратносовместимо: сайт их пока игнорирует
  (в будущей фазе сможет учитывать `hidden`).
- OneDrive иногда повреждает кэш Next (`Cannot find module './xxx.js'`). Лечится
  удалением `.next` и `node_modules/.cache` в корне сайта и перезапуском.
